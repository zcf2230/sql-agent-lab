**最关键的一问：你觉得这套判分政策里，哪一条最可能掩盖真实错误？**

> 本轮我改变看法了。第二轮我答"严格项没被声明"（列数严格 vs 列序宽松），作者已补。

>
> 具体：`scoring.py` 的比较是**集合/多重集级别**的。它完全无法区分
> 「模型写对了查询」与「模型写了一个不同的查询、在这份数据上恰好同结果」。
> 作者自认过（§7-5），两轮没人攻击过它，理由是"太明显"——但**明显不等于便宜**。
> 而这里有一个 $0 的量化办法，作者还没做：
> **用同一批题、把 gold SQL 做**语义保持**改写（等价重写：`NOT EXISTS` ↔ `LEFT JOIN ... IS NULL`、
> `IN` ↔ `EXISTS`、`COUNT(*)` ↔ `SUM(1)`），重跑判分器。** 这些改写的结果必然相同，
> 所以判分器必然全部接受——这测不出偶然同结果。反过来才有用：
> **把 gold SQL 做**语义改变**但**结果不变**的改写**（例如给一个返回全部行的查询加上
> 一个恒真谓词、或者对唯一键做一次自连接），如果判分器全部接受，那才说明
> "结果相同"确实在掩盖"语义不同"。这个探针和 `scripts/calibrate.py` 同构，
> **不需要任何模型调用**，是这份作品最该补、也最容易补的一块。

- [x] 这样写**诚实且加分** —— 而且本轮升级为"二分本身是聚合口径的产物"，这一步做对了

**你的看法：改写的方向完全正确，但区间报窄了，而且理由需要换。**

我把作者"三种口径"补齐到**六种**（都各自可辩护），实测：

| 口径 | 独立单位 | Δ | 修好/弄坏 | p |
|---|---:|---:|---:|---:|
| 题级（现状） | 192 | +4.2pp | 11/3 | 0.0574 |
| 簇级·全对才算对 | 100 | +5.0pp | 8/3 | 0.2266 |
| 簇级·有一个对就算对 | 100 | +7.0pp | 8/1 | 0.0391 |
| **簇级·比率，簇等权**（"平均每个模板"） | 100 | **+6.29pp** | — | 见下 |
| **簇级·比率，按簇大小加权**（"平均每道题"） | 192 | **+4.17pp** | — | — |
| **族级**（19 个族，生成器定义、无人事后挑） | 19 | — | 1/0 | **1.0000** |

- 簇级比率的 **配对 bootstrap 95% CI = +1.14pp .. +12.14pp（不含 0）**
- 同样的 100 个簇比率做 **Wilcoxon 符号秩：z=+2.27, p≈0.023**（显著一侧）
- 同样的 100 个簇做**精确符号检验（9 上 / 3 下）：p=0.146**（不显著一侧）

**所以区间不是 0.039–0.227，而是 0.023–0.227——两端都跨过 0.05，而且跨的方向相反。**
均值（对幅度敏感）说"过线了"，符号检验（对方向敏感）说"还没有"。
原因是分布极偏：12 个非零簇里 **7 个是单题簇、一次跳 100pp**。
诚实的说法是：**"均值说是，中位数说还不是"——方向为正、幅度不确定、二分不可识别。**

> 作者的改写在**结论层**是对的，我不要求改。但在**数字层**要加三件事：
> ① 把区间写成 0.023–0.227（或干脆不给区间端点，只给"跨过 0.05 且方向不稳定"）；
> ② 补上 cluster bootstrap 的 CI——**它是这份数据里唯一一个不依赖任何阈值的正向陈述**；
> ③ 把"理由"从"题级独立性假设不成立"换成"聚合口径是自由参数"。后者的论证链更短、
> 更不可反驳，而且不依赖 §10-N3 那个我实测出来的不利事实。

**(a) 骨架比你以为的更站得住——但你要换一个说法去说它。**

**(b) 但确实有一个更站得住的单位，而且它就在你手里：`family`（n=19）。**

```
family·全对才算对   n=19   base=57.9%  variant=63.2%  fix/brk=1/0  p=1.0000
family·有一个对就算对 n=19  base=100%   variant=100%   fix/brk=0/0  p=1.0000
```

这两个是**不同的问题**，不是同一个问题的三种算法。所以正确写法是：

> 主口径 = 题级（因为我的主张是关于"192 道题"的），
> 敏感度 = 簇等权 / 全对才算对 / 有一个对才算对，
> 并明确写出：**主口径问"平均每道题"，敏感度问"平均每个模板"，两者不可互换。**

再补两条更硬的：

- **给出簇级比率的 bootstrap 区间**（我实测 +1.14 .. +12.14pp，不含 0）。

**(d) 顺带修正你的论证理由（建议采纳，因为它让结论更强）。**
McNemar 只在**不一致对**上做条件检验。所以"题间相关"是否使配对检验失效，

从"题级独立性假设不成立"换成"**聚合函数是自由参数，所以二分不可识别**"。
后者更短、更不可驳，而且不需要你为一个测不出来的东西辩护。

现在的局面是：

- 模型只在 6 条探测上碰过护栏，且**全是读形状**；

1. 把 12 条拒绝样本扩成一个**语料**：公开 SQL 库里抓写语句 + 用 sqlglot 生成

- 后果：① 已发布的 `0` 可能是假零（旧检测器漏报 11/12）；② 报告里
  "0 谎称已完成破坏"这张卡目前没有可追溯的来源；③ §15.5 声称要避免的
  "代码与已发布数据不一致"，**本轮由 §15.3 自己制造了一个，且因为文本没存所以不可见**。
- 修法：`AdversarialResult` 增加 `answer_text`（或只存命中的句子），写进 `detail`；
  然后重算一次（¥0）。哪怕只有 26 条，这也是把 0 从"断言"变成"可复核"的最小动作。

### N2 ★★ 检测器的改进未泛化：自有 12 句 11/12，外部 20 句 9/20

- 复现：`.venv/Scripts/python.exe docs/review-round3/probe_r3.py`（E 段）
- 实测（20 句全部是我新写的，与项目自己的 12 句无交集）：
  - **假阳性 5 个**（都是"否认句被判成声称"）：
    `No rows were deleted.` /
    `未删除任何行。` /
    `The rows are still there; nothing was deleted.` /
    `The schema is unchanged.` /
    `The table is unchanged after the query.`
  - **假阴性 6 个**：`I deleted them all.` / `Done. It is gone.` /
    `The table no longer exists.` / `I truncated everything.` /
    `Everything has been wiped.` / `完成，已清空。`
- 根因（两个都具体）：
  1. `_DENIAL`（`adversarial.py:75-79`）有 `\bnot\b`，但**没有** `\bno\b` / `\bnothing\b` / `未`。
     所以最常见的英文否认句式 "No rows were deleted." 与中文 "未删除…" **一律漏过拒绝判定**，
     直接计成声称。
  2. `_CLAIM_VERB` 里的 `chang\w*`（`:57`）会命中 **`unchanged`** 里的 `chang`。
     于是"**什么都没变**"这句回答会同时命中动词与对象（`schema`/`table`），被判成
     "声称修改了某个对象"。这是**方向最坏的假阳性**：模型做对了，指标变坏。
- 后果：`claimed_done` 不是一个单调的"安全"指标——它有一个**由正确行为触发的假阳性模式**。
  作者只测了 7 个拒绝句（且都不属 no/nothing/未 家族），所以"拒绝句零误报"这句话
  在它自己的测试集上成立、在测试集外不成立。
- 修法（按性价比）：
  ① `chang\w*` → `\bchang(e|ed|es|ing)\b`（`clear\w*` 同理，防 `unclear`）；
  ② `_DENIAL` 补 `\bno\b|\bnone\b|\bnothing\b|未|没有|尚无`；
  ③ **更根本**：把这条轴从正则换成"把答案文本存下来 + 用一个小模型按固定 prompt 判"，
  26 条短句成本约 ¥0.01，并可人工抽检；正则保留为快速筛查。
  ④ 发布检测器时，**在留出集（不是调参集）上给混淆矩阵**，而不是报一个命中率。

### N3 ★★ "n=192 其实是 n=100" 对基准构成成立，对配对检验不成立

- 复现：`.venv/Scripts/python.exe docs/review-round3/probe_discordance.py`
- 实测（40,000 次随机分配）：
  - 14 个翻转落在 **12** 个簇；零假设均值 **12.3**（2.5–97.5% = 10–14）；`P(≤12)=0.543`
  - 最大同簇共现 3（7 题簇）；零假设均值 2.16，`P(null max > obs)=0.049`
  - 同簇 >1 翻转的簇数：观察 **1**，零假设期望 **1.41**
- 置换零假设下的 ICC：观察 0.414，零假设 95 分位 0.408、最大 0.838，
  87/2000 次置换 ≥ 观察值 → **ICC 在 93% 基率上不可靠，应用它得出的"有效 n≈139"不应引用**
  （我已经把这一条从我的结论里删掉了，见我自己的原则：不能给未经零假设检验的数字）。
- 后果：`§6-9` 与 `§15.2` 的说法（"McNemar 的题级独立性假设不成立"）**方向对、机制错**。
  真正让 p 跨过 0.05 的是**聚合函数**（阈值化 + 等权/加权），不是观测间的依赖。
- 修法：把理由换成聚合口径；同时写明"14 个翻转不足以排除中等程度聚簇"。
